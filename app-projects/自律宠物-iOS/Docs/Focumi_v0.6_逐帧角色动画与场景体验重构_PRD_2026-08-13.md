# Focumi v0.6 PRD：逐帧角色动画与场景体验重构

> 状态：**v0.6 PRD 已冻结；Gate 0 已获准进入。** 除发现硬冲突外，不再继续润色 PRD。  
> 版本定位：`0.6.0` 体验重构候选；当前真机 `0.5.0 (7)` 只作为可信 Blocking、计时、Return 与 Live Activity 的功能底座。  
> 核心判断：Focumi 当前差距不是“少几个动画”，而是角色没有通过连续表演组织产品体验。本版本必须先把 Milo / Max 做成可信、稳定、有性格的数字伙伴，再把既有工具能力接回场景。  
> 参考边界：学习 Cat on Chair 的手工感、角色主导、场景连续性与体验密度；不得复制其猫坐椅子、房间布局、插画、家具、礼物、鱼币、商店、失败垃圾或具体动作。

---

## 0. 决策摘要

### 0.1 一句话目标

让用户第一次开始、暂离后回来、完成专注时，明确感觉到：

> **Milo / Max 不是贴在计时器上的图片，而是真的注意到我、陪我做事、等我回来，并和我一起完成。**

### 0.2 本版本不是

- 不是继续替换配色、图标或文案；
- 不是给静态 PNG 加呼吸、缩放、漂浮和淡入淡出；
- 不是用 3–6 张独立 AI 图快速轮播冒充角色动画；
- 不是一次性扩建房间、家具、货币、商城、签到或宠物养成系统；
- 不是降低 Blocking 真实性来换取更顺滑的视觉叙事。

### 0.3 本版本必须交付

1. 先用最小充分的角色约束完成 Milo `Return Together` 表演验证；
2. Return 表演成立后，再决定完整 production pipeline 与 Character Bible 的投入深度；
3. 一个原创、连续的 Focumi 核心场景；
4. `Start Together`、`Return Together`、`Completion` 三段达到可独立录屏传播的逐帧 Signature Animation；
5. Focus / Waiting / Tap 等低频陪伴动作；
6. UI、角色、场景、声音、触感组成同一条连续体验；
7. Reduce Motion、VoiceOver、低性能与中断状态的等价落点；
8. 真机逐帧、性能、系统状态真实性与完整流程验收。

### 0.4 四项制作校准

| 分歧 | v0.6 最终决策 |
|---|---|
| 逐帧动画规格 | **先证明 Return 的表演成立，再决定生产体系做到多专业。** Gate 0 不要求先建立完整 pipeline。 |
| Character Bible | **Return 前只做 Lite。** 只冻结足以避免该镜头角色漂移的不变量；Return 通过后再补完整模型表。 |
| drawings 数量 | **只作预算参考，不是完成 KPI。** 不得按数量验收、不得为凑帧增加无意义补间。 |
| Completion 隐喻 | **书签属于 Waiting；Completion 使用原创盖章。** 两个 Moment 不再共用同一隐喻。 |

### 0.5 废止的旧标准

旧 Motion Bible 中以下帧数不再作为正式品质标准：

- Idle 3–4 帧；
- Pact 2 帧；
- Start / Return 4–6 帧；
- Focus 3–5 帧；
- Completion 6–10 帧。

它们可临时保留为降级占位或历史资产，但不得进入 v0.6 正式体验验收。

## 1. Problem Statement

当前 Focumi 已具备计时、目标、Family Controls、Shield、必要使用、Return、完成与 Live Activity 等功能底座，但用户感受到的仍是“宠物主题的专注工具”，而不是“陪我一起努力的数字伙伴”。

根因包括：

1. **角色动作过少。** 少量静态帧只能表现状态切换，无法表现注意、犹豫、蓄力、落地、呼吸和情绪余韵。
2. **缺少动作因果。** 用户点击开始后，角色没有先听见、看向目标、移动到位置、安顿下来；画面直接切换，缺少可信的动作链。
3. **角色不稳定。** 独立生成的图片容易出现脸型、头身比、花纹、配饰、透视和画法漂移。
4. **没有共同空间。** 首页、Focus、Return、Completion 像不同卡片页面，角色没有生活在一个连续世界里。
5. **UI 压过角色。** 大量说明、边框、标签和状态文案抢占主舞台，宠物更像装饰图。
6. **没有逐帧质量门禁。** 只检查“资产存在、能播放、不卡住”，没有检查轮廓抖动、体积变化、接触点滑动、节奏、表演和角色辨识度。
7. **动效与状态机割裂。** 动画常被当作 phase 切换后的附属效果，而不是围绕用户动作设计的可中断表演。

因此，继续在 v0.5 页面上添加更多动画不会解决问题。必须先以最小投入证明 Return 表演成立；只有通过后，才建立与目标质量相称的动画制作体系和单一场景，再进行工程接入。

## 2. Product Principle

### 2.1 Utility × Character × Delight

- **Utility：**目标、计时、App Blocking、Return、Live Activity；证明产品真实有用。
- **Character：**Milo / Max 的身份、行为、注意力和性格；形成情感连接。
- **Delight：**逐帧动画、场景变化、转场、声音、Haptic 与完成反馈；形成购买欲与传播欲。

三者不是排序替代关系。Blocking 是不可撒谎的底座；Character 与 Delight 是本版本的主要产品工作。

### 2.2 动画的第一性原理

每个动作必须回答四个问题：

1. 角色看见了什么？
2. 角色为什么现在行动？
3. 角色的重量和注意力如何转移？
4. 动作结束后，用户和角色的关系发生了什么？

无法回答这四个问题的动画属于装饰，不进入 P0。

### 2.3 原创场景命题

v0.6 只建设一个核心空间：

> **“正在完成的这一页”——一张温暖、安静的书桌／阅读页空间。Milo / Max 陪用户打开这一页；用户暂离时替他守住书签；用户完成时一起为这一页盖下完成章。**

场景可包含：打开的书、本子、铅笔、书签、窗边光影和少量植物剪影。不得出现 Cat on Chair 的猫坐椅子构图、同类房间、家具收集或礼物经济。

## 3. Experience Architecture

### 3.1 单场景连续流程

```text
Idle Desk
   ↓ 用户写下目标
Pet Notices the Page
   ↓ Start Together
Pet Settles Beside the Page
   ↓ Focus Together
Pet Quietly Accompanies
   ↓ Temporary Detour
Pet Holds the Bookmark
   ↓ Return Together
Pet Notices User and Reopens the Page
   ↓ Legal Completion
Pet Places the Focumi Completion Stamp
```

页面可以滚动或展示必要系统信息，但视觉上始终是同一个空间，不能每进入一个 phase 就更换互不相关的海报式背景。

### 3.2 信息层级

主舞台顺序：

1. Milo / Max 当前行为；
2. 用户与宠物共同完成的目标；
3. 剩余时间；
4. 单一主要动作；
5. Blocking 的诚实系统状态。

权限、App 选择和技术说明在首次设置或轻量抽屉中完成。已准备状态下不得长期占据主场景的大卡片。

### 3.3 角色不是按钮皮肤

角色必须在下列用户行为中产生不同、因果明确的反应：

- 用户开始输入；
- 用户确认目标；
- 用户切换时长；
- 用户开始；
- 用户轻触宠物；
- 用户暂时离开；
- 用户回来；
- 用户继续；
- 用户完成；
- 用户主动结束。

同一个通用“抬头”动作不得复用于所有事件。

## 4. Character Bible：Lite First

### 4.1 Gate 0 前的 Lite Character Bible

在制作 Milo Return animatic 前，只冻结这个镜头不可缺少的约束：

- Milo 的正面与 3/4 正面基准；
- 头身比例、脸型、眼睛、耳朵、额头 M 纹和鼠尾草领巾；
- 等待、发现用户、重新投入三张关键情绪姿态；
- 与书页、书签的相对尺度和接触点；
- 本镜头固定色板、线条与纹理示例；
- 五条最容易发生的角色漂移禁例。

Lite Bible 只服务于验证 Return 表演，不能被包装成完整角色生产体系。此时不要求先完成 Max，也不要求完整 turnaround、全部表情或所有基础动作。

### 4.2 Return 通过后的完整 Character Bible

只有用户确认 Return 的表演成立后，Milo 与 Max 才各自补齐：

- 正面、侧面、背面、3/4 正面、3/4 背面 turnaround；
- 中性、好奇、专注、等待、发现用户、满足六种表情；
- 站、坐、卧、迈步、伸爪五种基础结构；
- 眼睛、耳朵、嘴、尾巴、领巾与四肢的分层说明；
- 固定色板、线条粗细、纹理密度、阴影规则；
- 与书、本子、铅笔、书签的尺寸关系和接触点；
- 每个视角的禁止漂移示例。

完整模型表未获用户确认，不得批量制作 Start、Completion、ambient 或 Max 全动作；但它不是 Milo Return animatic 的前置阻断。

### 4.3 身份不变量

每一帧必须保持：

- 头身比例和头部体积；
- 眼睛间距、鼻口位置与耳朵轮廓；
- Milo 的额头 M 纹、虎斑方向、白口鼻、鼠尾草领巾；
- Max 的白色额纹、黑白区域、白尾尖、灰蓝格纹领巾；
- 爪子数量、关节方向、尾巴长度；
- 统一的复古手绘线稿、彩铅与纸张颗粒语言。

Return 验证阶段以 Lite Bible、前后关键姿态和人工连续性校正约束；进入正式生产后，升级为完整模型表约束。不得逐帧独立向生成模型输入文本后直接采用。AI 可以辅助概念、补间草稿或清理建议，但不能替代连续性判断。

### 4.4 性格差异

**Milo：**更安静、细腻、观察型。动作幅度小，眼神和尾尖先表达注意，安顿时轻轻压住书页。

**Max：**更主动、笨拙可爱、热情。耳朵和身体先反应，移动略快，坐下后会重新调整一次姿势。

两者不能只换皮。相同情节必须使用不同 timing、pose 和 secondary action。

## 5. Frame-by-Frame Animation Standard

### 5.1 分阶段制作顺序

#### Return 表演验证阶段

Gate 0 只执行最小链路：

1. **Beat sheet：**一句话描述 Return 的情绪与因果；
2. **Lite Character Bible：**只冻结该镜头必要不变量；
3. **Thumbnail poses：**3–8 个黑白小姿态；
4. **Animatic：**低精度定时预演；
5. **静音用户判断：**用户能否看懂“它发现我回来，并和我继续”。

如果表演不成立，只调整情节、姿态和 timing，不建立完整 production pipeline、不批量生成正式帧、不接入 App。

#### Return 通过后的正式制作阶段

确定值得继续后，每个正式动作再依次通过：

1. **Beat sheet：**一句话描述情绪与因果；
2. **Thumbnail poses：**3–8 个黑白小姿态，先审轮廓和表演；
3. **Animatic：**低精度定时预演，审节奏与镜头；
4. **Key poses：**接触、重心和情绪最清晰的关键帧；
5. **Breakdowns：**定义动作弧线、拖尾、超越和回弹；
6. **In-betweens：**补间，不允许自动插帧直接成为正式帧；
7. **Cleanup：**统一体积、轮廓、花纹和线条；
8. **Color / texture：**统一色板与颗粒，不让纹理逐帧闪烁；
9. **Compositing：**与场景光影、UI 和声音合成；
10. **Frame review：**逐帧与实时速度双审；
11. **Device proof：**真机录屏、性能、中断和降级验收。

任一步未通过，不得跳到批量工程接入。

### 5.2 播放与绘制基准

- App 以 60Hz 显示合成；角色正式绘制通常采用 12 drawings/sec 的 hand-drawn on-twos 节奏。
- 快速反应、落爪、眨眼等关键 100–250ms 区间可局部使用 on-ones，提高冲击和清晰度。
- 安静停顿允许 hold frame，但 hold 必须是主动节奏设计，不能用来掩盖帧数不足。
- 不要求所有动作机械达到同一帧数；以动作可读、重量可信和性格明确为准。
- UI 位移、光影和相机合成可使用系统 60fps 插值；角色身体表演不得只靠整体 scale、offset、rotation 完成。

### 5.3 正式动作制作量参考

下表只用于估算人力、包体与排期，**不是下限、完成定义或验收 KPI**。一个动作可以用更少 drawings 达到更好表演，也可能需要更多；团队不得为了达到数字增加无意义补间，也不得因达到数字停止修正表演。

| 动作 | 目标时长 | 独立角色绘制建议 | 循环/一次性 | 品质重点 |
|---|---:|---:|---|---|
| Idle breathing | 4–6s | 24–36 drawings，包含长 hold | 无缝低频循环 | 呼吸、眨眼、耳朵、尾尖不同步，不能机械摆动 |
| Goal noticed | 0.8–1.2s | 10–16 drawings | 一次性 | 视线先到、耳朵后动、身体最后响应 |
| Duration response | 0.5–0.8s | 6–10 drawings | 一次性、可替换 | 克制，不形成反复点击奖励循环 |
| Start Together | 1.4–2.0s | 18–26 drawings | 一次性 | 预备→移动→接触书页→安顿→余韵 |
| Focus ambient A | 5–8s | 30–48 drawings，含 hold | 低频循环 | 阅读/陪伴，动作不能抢计时信息 |
| Focus ambient B | 4–7s | 24–40 drawings，含 hold | 稀有替换循环 | 换姿势、抬眼、轻压书页 |
| Tap response | 0.7–1.0s | 8–14 drawings | 一次性、冷却 | 注意到用户，而不是跳跃或撒娇奖励 |
| Waiting | 2.0–3.0s 入场 + 静态 | 16–24 drawings | 一次后静止 | 放下动作、守住书签，不表现责备 |
| Return Together | 1.8–2.5s | 22–34 drawings | 一次性 | 发现→确认→重新翻页→一起安顿 |
| Completion | 2.5–3.5s | 30–44 drawings | 一次性 | 完成页面、盖下完成章、看向用户、满足余韵 |
| Gentle end | 1.0–1.5s | 12–20 drawings | 一次性 | 温柔收起，不制造失败或内疚 |

Milo 与 Max 的绘制不能通过简单变形复用；允许共享情节结构，但关键姿态、节奏与 secondary action 必须体现性格差异。

### 5.4 十二维逐帧审查

每个镜头逐帧检查：

1. silhouette 是否一眼可读；
2. 头部与身体体积是否漂移；
3. 重心是否沿可信弧线移动；
4. 爪、书、地面的接触点是否滑动；
5. 预备动作是否先于主动作；
6. 主动作后是否有 overshoot / settle；
7. 眼神是否先于头和身体引导注意；
8. 耳朵、领巾、尾巴是否具有合理拖尾；
9. 毛纹、领巾和线稿是否闪烁；
10. 透视与场景尺度是否稳定；
11. Milo / Max 的性格是否在静音状态仍可辨认；
12. 去掉文字后，用户是否仍能理解发生了什么。

出现脸型跳变、四肢变形、接触点漂移、纹理闪烁、自动插帧融化或角色忽大忽小，直接 FAIL。

## 6. Signature Animation Specification

### 6.1 Start Together

**用户感受：**“它听见了我要做的事，现在真的来陪我了。”

动作节拍：

1. 用户确认目标；
2. Milo 尾尖停下／Max 耳朵竖起；
3. 视线落到目标页；
4. 角色移动到书页旁；
5. Milo 轻压书页／Max 坐下后调整一次位置；
6. 页面和倒计时自然进入；
7. 角色进入安静 Focus 呼吸。

要求：

- 1.4–2.0s，不得为了快而删掉预备和安顿；
- 用户可以立即中断或结束，动画不锁住业务状态；
- 一次轻 Haptic 对应用户开始，不代表 Shield 已生效；
- Blocking 仅显示“Focumi 已请求 iPhone 暂时限制所选 App”；
- 首次看到应具有值得录屏的完整起承转合。

### 6.2 Return Together

**用户感受：**“它一直在等我，而且真的注意到我回来了。”

动作节拍：

1. Waiting 中角色替用户压住／守在书签旁安静停留；
2. 用户点击返回；
3. 角色先听见／察觉，再抬头；
4. 与用户形成短暂视线确认；
5. 重新打开或推回目标页；
6. 角色回到 Focus 位置；
7. 倒计时与目标重新成为视觉主位。

要求：

- 1.8–2.5s，是全 App 最重要的 Signature Moment；
- 不允许 `waiting.png → focusing.png` 直接切换；
- Return 请求只触发一次，重复回调不得重播或重复 Haptic；
- 转场完成不能作为 Shield 已重新保护的证据；
- 如果系统状态需要注意，角色保持中性，文案说明下一步，不表现失望。

### 6.3 Completion

**用户感受：**“我们确实一起完成了一件事，这个小瞬间值得留下。”

动作节拍：

1. 角色完成最后一个陪伴动作；
2. 看一眼完成的页面；
3. 合上或整理页面；
4. 与用户一起盖下一枚原创 Focumi 完成章；
5. 看向用户；
6. 停留在满足、安静的最终姿态。

要求：

- 2.5–3.5s，只播放一次；
- 无金币、XP、烟花、宝箱或夸张胜利动作；
- CTA 从动画开始即可访问，不得强迫用户看完；
- 只在合法完成触发，提前结束、撤权、超时异常均不得触发；
- 最终帧本身必须可作为 App Store 截图和 Reduce Motion 静态落点。

## 7. Scene, UI, Sound and Haptic

### 7.1 场景连续性

- 摄像机与书桌主透视固定；状态变化通过角色、书页、书签、光线和局部 UI 完成。
- 不在不同 phase 突然更换画风、纸张比例或角色尺度。
- 背景只做极低频光影、叶影或纸张呼吸；不得使用持续粒子、漂浮装饰和无意义 sparkle。
- UI 卡片减少到必要信息，不能盖住角色的关键表演区。

### 7.2 UI Motion

- 角色动，UI 就克制；UI 大幅转场时角色保持清晰姿态，避免同时争夺注意力。
- 目标和计时应像场景中的页签，而不是独立 Dashboard。
- UI 过渡使用系统 60fps；角色动画采用自身 hand-drawn cadence。
- 输入、选择 App 和权限仍使用可访问的原生控件，不为风格牺牲可用性。

### 7.3 声音

声音默认可关闭，且不承担理解所需信息。最小声音集：

- 翻页；
- Waiting 中书签轻触纸面；
- Completion 中印章落下的柔和纸面声；
- 铅笔或布料的极轻拟音；
- 可选、低音量角色呼吸或鼻音，不做高频叫声。

不得从无明确商业许可的素材库取用。音乐与拟音分别控制；静音模式、其他音频和中断恢复必须符合 iOS 预期。

### 7.4 Haptic

- Start / Return：一次 `.light`；
- Completion：一次克制的 success pattern；
- 时长选择：selection；
- 角色 Tap：selection，保留冷却；
- Haptic 永不表示 Apple Shield 已确认成功。

## 8. Technical Delivery Decisions

### 8.1 表现层与事实层分离

- 继续复用现有 Session、deadline、Family Controls、ManagedSettings、Return、Live Activity 真值来源。
- 新增独立、短命、可中断的 `CompanionPerformanceState`，只描述角色当前表演，不持久化为系统成功。
- 业务 phase 决定允许播放哪些表演；表演结束不得反向篡改业务事实。
- 重复通知、热启动 reconciliation、前后台切换不能导致 Signature Animation 重复结算。

### 8.2 动画载体

实施前做一个不超过两天的技术 spike，对同一 2 秒样片比较：

1. 透明 HEVC 一次性动画；
2. Texture Atlas / SpriteKit 或等价原生逐帧播放器。

比较指标：透明边缘、纸张纹理、内存峰值、包体、解码功耗、首帧延迟、精确暂停／中断、Reduce Motion 落点和 iPhone 真机稳定性。

决策原则：

- Signature 一次性长动画优先选择画质稳定、首帧可靠的预渲染方案；
- Tap / Idle / Focus 等需即时切换的短动作优先选择可精确控制帧与中断的 atlas 方案；
- 不因框架流行而引入 Rive / Lottie；只有它们能保留手绘纹理、授权合规且 spike 数据更优时才采用；
- 不新增服务器，动画全部本地可用。

### 8.3 资产规格

- 原始制作保留分层源文件与无损 master，不直接在 xcassets 中编辑唯一源；
- 每个动作保存 frame manifest：角色、动作、版本、画布、帧率、drawings、总时长、loop、anchor、contact point、Reduce Motion final frame；
- @2x / @3x 由批准 master 派生，不放大低分辨率 AI 图；
- 透明边缘、色域、premultiplied alpha 与压缩必须在真机检查；
- App、Live Activity、Shield 使用分别优化的资产，不把 App 大图机械缩小到系统表面。

### 8.4 包体与性能预算

- v0.6 新增角色动画压缩后总预算目标不超过 80MB；超过 60MB 必须给出每动作收益和裁剪方案；
- 标准真机播放时主线程不得因逐帧解码持续掉帧；
- 首个 Signature 动画首帧延迟目标 <100ms；
- 播放期间 UI 点击响应目标 <100ms；
- 内存 warning 后必须安全降级到静态最终帧，不崩溃、不黑屏；
- 低电量模式可减少 ambient 频率，但不得删除 Start / Return / Completion 的语义。

## 9. User Stories

1. 作为第一次使用 Focumi 的用户，我希望 Milo / Max 会注意到我写下的目标，以便我感到它在参与，而不是被贴在页面上。
2. 作为开始专注的用户，我希望伙伴通过完整动作来到书页旁并安顿下来，以便“开始一起专注”有真实发生感。
3. 作为正在专注的用户，我希望伙伴保持安静、低频、自然的陪伴，以便它有生命力但不会打扰我。
4. 作为轻触伙伴的用户，我希望得到一次符合角色性格的回应，以便互动有温度但不会成为点击游戏。
5. 作为需要暂时使用 App 的用户，我希望伙伴替我留着这一页，以便我不会因为离开而感到失败或内疚。
6. 作为返回 Focumi 的用户，我希望伙伴先发现我，再和我重新打开目标页，以便 Return 成为产品最有记忆的瞬间。
7. 作为完成专注的用户，我希望与伙伴共同为这一页盖下完成章，以便这次努力有明确而安静的情绪收束。
8. 作为主动结束的用户，我希望伙伴温柔收起当前页面，以便产品不会责备我。
9. 作为 Milo 用户，我希望 Milo 的动作始终安静、细腻且身份稳定，以便我能形成角色感情。
10. 作为 Max 用户，我希望 Max 的动作更主动、略带笨拙且身份稳定，以便它不是 Milo 的换皮。
11. 作为开启 Reduce Motion 的用户，我希望直接看到完整、漂亮的关键终态，以便不观看连续动态也能理解和完成流程。
12. 作为 VoiceOver 用户，我希望目标、时间、真实状态和 CTA 保持正确顺序，以便角色表演不会阻塞任务。
13. 作为低性能设备用户，我希望动画可以降级为静态姿态，以便 App 不崩溃、不发热且功能完整。
14. 作为关心 App Blocking 的用户，我希望视觉与触感不会假装 iOS 已保护成功，以便我能够信任 Focumi。
15. 作为可能购买 $2.99 的用户，我希望三个关键瞬间足够精致、原创、值得留下，以便我觉得这款 App 值得购买。
16. 作为内容观看者，我希望即使不看说明也能从录屏理解宠物在陪用户开始、等待、返回和完成，以便产品具备自然传播能力。

## 10. Production Plan and Gates

### Gate 0：Return 表演证明

只做 Milo 的 `Return Together` beat sheet、Lite Character Bible、storyboard / animatic，不接 App，不先搭完整 production pipeline。

通过条件：用户看静音样片能复述“它发现我回来了，并和我继续”，并认可角色反应有生命感；未通过则只改表演，不补完整 Bible、不生产正式帧、不写工程代码。

### Gate 1：完整角色冻结决策

仅在 Gate 0 通过后，决定 production pipeline 的专业深度，补齐 Milo / Max 完整模型表与性格动作测试，各制作一个 1 秒发现用户动作。

通过条件：随机抽帧仍能一眼辨认角色；头身、花纹、领巾和画风稳定。

### Gate 2：三段高精度样片

先完成 Milo 的 Start / Return / Completion 全精度成片与场景合成。Waiting 明确使用“守书签”，Completion 明确使用“盖完成章”。

通过条件：逐帧审查 PASS、正常速度自然、用户确认“值得录屏”，再生产 Max 版本。

### Gate 3：工程 Spike

比较两种动画载体并在一台低端支持设备和当前真机上测首帧、内存、掉帧、透明边缘与中断。

通过条件：数据支持选型；无可靠方案则先静态降级，不批量导入全部资产。

### Gate 4：核心流程接入

接入 Start → Focus → Waiting → Return → Completion，保持既有业务真值。

通过条件：重复事件不重播、动画可中断、目标和倒计时不丢失、Shield 语义不越界。

### Gate 5：系统与无障碍

完成 Reduce Motion、VoiceOver、Dynamic Type、低电量、音频中断、后台恢复和系统表面适配。

### Gate 6：真实 Beta

先 5–10 名朋友，再陌生用户。分别记录：

- 是否主动提到宠物“像在陪我”；
- 是否主动录屏、截图或分享；
- 是否完成核心动作；
- 是否无催促第二次使用；
- 是否愿意真实支付 $2.99。

动画完成、朋友喜欢或下载均不等于商业绿灯。

## 11. Testing Decisions

### 11.1 自动化

- 业务状态与表演状态分离测试；
- Start / Return / Completion 每次合法事件只发出一个 performance token；
- 重复 lifecycle / reconcile 不重复播放、不重复 Haptic；
- 提前结束、撤权、错误与超时不触发 Completion；
- Return 仍只发出一次 reapply 请求；
- Reduce Motion 选择正确静态落点；
- 内存／解码失败选择静态 fallback；
- 中英文动态宠物名与真实系统文案测试；
- Live Activity 仍只投影本地已知状态。

测试外部可观察行为，不硬测 SwiftUI 私有实现或逐帧播放器内部计时器。

### 11.2 逐帧资产 QA

每个动作输出 contact sheet、onion-skin 对比、轮廓叠加和实时预览：

- 随机抽查首、中、末与接触关键帧；
- 轮廓体积、接触点和角色身份无跳变；
- 无透明绿边、黑边、halo、纹理闪烁；
- 循环首尾速度与姿态连续；
- 60Hz 显示下 cadence 无明显顿挫；
- 静音仍能理解故事。

### 11.3 真机矩阵

- Milo / Max 各跑完整流程；
- 普通字号与 AXXXL；
- Reduce Motion 开／关；
- VoiceOver 主路径；
- 静音、音乐、其他 App 音频中断；
- 前后台切换、锁屏、冷启动恢复；
- Shield、临时开放、Return、重新限制；
- Live Activity / Dynamic Island compact、expanded、minimal 与清理；
- 低电量模式与内存压力降级；
- 录屏逐帧检查掉帧、黑帧、首帧延迟、裁切和残影。

本地 build、模拟器截图、动画视频或开发者自述不能替代真实系统表面的真机证据。

## 12. Acceptance Gate

v0.6 只有同时满足以下条件才可进入 TestFlight 候选：

1. 用户先批准 Milo Return animatic 的表演成立；
2. Return 通过后，用户批准 Milo / Max 完整角色模型表；
3. 三段 Signature Animation 的 animatic 与最终成片均获批准；
4. 每段通过十二维逐帧审查，无明显 AI 漂移或接触点滑动；
5. Milo / Max 表演具有可辨认的性格差异；
6. Waiting 的书签与 Completion 的盖章语义清晰且不混用；
7. 单场景流程连续，UI 不再压过角色；
8. 全部动画可中断，业务状态不依赖动画结束；
9. Reduce Motion、VoiceOver 与静态 fallback 可完成等价任务；
10. 自动测试、全 target build 和真机完整流程闭环；
11. Shield / Return / Live Activity 的真实性边界未退化；
12. 包体、内存、首帧延迟与掉帧在预算内；
13. 至少 5 名非制作参与者在无引导观看后，能正确描述 Start / Return / Completion 的情节；
14. 不包含任何 Cat on Chair 的受保护角色、布局、插画、家具、礼物或经济系统复制。

“帧数达到”“能播放”“截图漂亮”“用户说可爱”均不能单独构成 PASS。

## 13. Out of Scope

- 家具商城、房间装修、货币、鱼币、礼物售卖；
- XP、等级、签到、连续天数、每日任务；

- 多房间、几十只宠物、服装 inventory；

- 医疗化或 ADHD 宣传；
- 新服务器与账号系统；
- 在 v0.6 动画品质通过前建立付费墙；
- 正式 App Store 发布。

## 14. First-principles / Red-team Review

### 前提

- 用户购买的不是动画数量，而是可信、独特、持续的角色体验；
- AI coding 可以降低工程门槛，不能自动提供表演、审美和逐帧一致性；
- Blocking 若撒谎，再精致的动画也会破坏信任；
- 一个人／小团队无法同时高质量建设角色动画、多个房间和复杂经济系统。

### 攻击与误用方式

1. 用更多 AI 图和更高帧率掩盖角色漂移；
2. 用整体缩放、平移和淡入淡出冒充逐帧表演；
3. 先批量生成 Milo / Max 全动作，再发现模型不一致；
4. 为追求 Cat on Chair 的丰富度复制其家具、礼物或房间；
5. 动画播放结束后才更新业务状态，造成按钮阻塞或重复命令；
6. 用 Haptic、庆祝或角色开心暗示 Shield 已确认；
7. 为了“可爱”加入无限点击、收集和留存负担；
8. 只在高端模拟器审查，忽略真机解码、内存和系统入口。

### 阻断证据

- Milo Return Lite Bible 与 animatic 批准记录；
- Return 通过后的完整模型表批准记录；
- animatic 先于正式成片；
- contact sheet、轮廓叠加与逐帧 FAIL/PASS；
- 技术 spike 的真机数据；
- 状态机与 performance token 自动测试；
- 真机 Shield / Return / Live Activity 独立记录；
- 原创性清单和参考排除清单。

### 残余风险

- 高品质逐帧动画的时间和成本显著高于当前资产替换；
- AI 辅助仍可能产生需要大量人工 cleanup 的不稳定帧；
- 本地高质量动画会增加包体、内存和解码复杂度；
- 精致体验可以提高试用与购买欲，但不能保证留存或付费；
- Apple 系统表面限制可能无法完全延续 App 内场景。

### 修正与闭环

- 先只制作 Milo Return Lite Bible 与 animatic，以最小成本验证表演方向；
- Return 不成立时不升级 production pipeline；用户批准后才补完整 Bible、制作 Milo 三段成片，最后扩展 Max；
- 先 spike 载体再批量导入，避免资产完成后发现技术不可用；
- 每一 Gate 都允许停止、降级或返工，不以进度压力跳过；
- 产品体验通过后仍单独执行真实用户 V-S-C-R 与 $2.99 行动验证。

## 15. 最终成功标准

用户第一次看到完整流程后，不需要我们解释“这里做了多少帧”，而会自然说：

> **“它真的在陪我。”**

如果用户只说“画风变可爱了”“动画比以前多了”，但没有感受到角色注意、等待、返回和共同完成，本版本仍然失败。
